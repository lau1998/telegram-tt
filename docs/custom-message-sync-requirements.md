# 定制功能：群/频道消息同步需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 定制功能 - 消息同步 |
| 当前版本 | v0.1 |
| 文档状态 | 需求评审稿 |
| 运行方式 | 服务端常驻运行 |
| 默认执行身份 | 当前登录账号 |
| 可选执行身份 | 指定 Bot |

## 2. 背景

用户需要将一个群组或频道 A 的新消息，自动同步到另一个群组或频道 B。

该能力需要在服务端持续运行，即使用户关闭 Telegram 页面，已启用的同步规则仍然继续执行。用户可以使用当前 Telegram 账号，也可以选择已经配置好的 Bot 作为执行身份。

## 3. 产品目标

用户可以通过左上角的“定制功能”入口创建并管理一条消息同步规则，配置来源对象、目标对象、执行身份和同步模式。

消息同步支持以下两种独立模式：

1. **保留来源转发**：使用 Telegram 原生转发语义，目标端保留来源信息。
2. **隐藏来源复制**：在目标端重新生成独立消息，不展示原始来源信息。

两种模式必须由用户明确选择，转发失败后不得自动切换为复制模式。

## 4. 功能入口与页面

### 4.1 左侧菜单

左上角菜单新增入口：

> 定制功能

点击后进入定制功能页面。

### 4.2 定制功能列表页

当前只展示一个功能：

- 功能名称：消息同步
- 功能说明：将一个群或频道的新消息同步到另一个群或频道
- 当前状态：未配置、草稿、运行中、已暂停、异常
- 操作：配置、启用、暂停、恢复、删除

“定制功能”是功能分类，“消息同步”是第一期唯一的功能类型。第一期只允许一条有效同步规则，后续再扩展多规则。

### 4.3 消息同步配置页

配置项包括：

| 配置项 | 说明 |
| --- | --- |
| 来源 A | 选择当前执行身份可以访问的群或频道 |
| 目标 B | 选择当前执行身份可以发送消息的群或频道 |
| 执行身份 | 当前账号或指定 Bot，默认使用当前账号 |
| 同步模式 | 保留来源转发或隐藏来源复制 |
| 规则状态 | 草稿、运行中、已暂停、异常 |

页面需要展示同步摘要：

- 来源 A → 目标 B
- 当前执行身份
- 当前同步模式
- 仅同步启用后的新消息
- 不同步历史消息
- 当前模式支持的消息类型
- 不支持内容的处理方式

## 5. 用户流程

### 5.1 创建规则

1. 用户点击左上角“定制功能”。
2. 进入“消息同步”功能。
3. 选择来源群或频道 A。
4. 选择目标群或频道 B。
5. 选择执行身份：当前账号或指定 Bot。
6. 选择同步模式。
7. 系统执行权限检查。
8. 用户保存规则，规则进入“草稿”状态。
9. 用户点击“启用同步”。
10. 系统显示二次确认。
11. 用户确认后，规则进入“运行中”。

### 5.2 启用确认

启用前显示：

> 启用后，来源 A 的新消息将自动发送到目标 B。请确认目标成员可以看到这些内容。

启用时记录来源会话的消息边界，只处理启用之后产生的新消息，不根据本地时间判断消息是否属于启用前或启用后。

### 5.3 暂停与恢复

暂停规则后：

- 不再创建新的同步任务。
- 已经进入发送阶段的任务允许完成。
- 尚未发送的任务不继续执行。
- 暂停期间产生的消息不补发。

恢复后只处理恢复之后的新消息。

### 5.4 删除规则

删除采用逻辑删除：

- 停止接收和发送新的同步任务。
- 已发送到目标 B 的消息默认保留。
- 尚未发送的任务取消。
- 已失效的 Worker 不得继续发送。

## 6. 执行身份

### 6.1 当前账号

服务端需要显式绑定用户的 Telegram 账号，不能仅依赖浏览器当前登录状态。

账号绑定需要支持：

- 手机号或二维码登录。
- 验证码验证。
- 2FA 验证。
- 查看已连接账号。
- 主动断开和撤销授权。

账号 Session 必须加密存储，不能以明文形式出现在数据库、队列、日志、监控和备份中。

### 6.2 Bot

用户可以配置 Bot 作为同步规则的执行身份。

Bot 需要满足：

- 已加入来源群或频道。
- 具备读取来源消息的能力。
- 已加入目标群或频道。
- 具备向目标发送消息或向频道发帖的权限。
- 群组场景正确配置管理员权限或隐私模式。

Bot 只能同步它实际能够接收和读取的消息。使用 Bot 时，来源和目标的权限检查必须独立执行。

Bot Token 只能存放在安全凭证存储中，不能写入普通业务日志或前端状态。

### 6.3 规则与执行身份绑定

每条规则必须绑定一个确定的执行身份。执行身份变化后，应重新执行来源和目标权限检查，并生成新的规则配置版本。

规则执行不能只依赖前端传入的群组名称、用户名或邀请链接，必须绑定稳定的会话标识。

## 7. 同步模式

### 7.1 保留来源转发

目标端使用 Telegram 原生转发消息：

- 保留来源群或频道信息。
- 保留原消息的转发语义。
- 优先支持常见文本和媒体类型。
- 目标消息可明确识别为转发内容。

页面需要提示用户：

- 目标成员可能看到来源信息。
- 来源作者、群组或频道信息可能被暴露。
- 目标受众可能比来源受众更广。

### 7.2 隐藏来源复制

目标端重新生成独立消息：

- 不展示原始来源群或频道。
- 不展示原始来源作者。
- 由当前账号或 Bot 作为发送者。
- 文本、格式、媒体说明和媒体文件需要重新构建。
- 相册需要整体聚合后重新发送。

复制模式是一次性内容复制，不代表目标消息与来源消息建立实时镜像关系。第一期不支持来源消息编辑和删除同步。

复制模式不应默认修改原消息正文。同步来源应在规则详情、同步记录和错误信息中标识。

## 8. 消息类型范围

### 8.1 第一期开启支持

- 文本。
- 基础富文本和文本实体。
- 图片。
- 视频。
- 音频。
- 普通文件。
- 媒体说明文字。
- 相册。

### 8.2 第一期不支持

- 历史消息补同步。
- 服务消息。
- 投票。
- 付款、账单和付费媒体。
- 抽奖。
- 实时位置。
- 评论区消息。
- 论坛 Topic。
- 回复关系。
- 来源消息编辑同步。
- 来源消息删除同步。

不支持的消息必须进入“已跳过”或“失败”状态，并记录可理解的原因，不能静默丢失。

## 9. 媒体和相册要求

### 9.1 媒体文件

媒体同步需要支持图片、视频、音频和普通文件，并设置：

- 支持的媒体类型白名单。
- 单文件大小限制。
- 执行身份对应的发送限制。
- 上传超时和失败重试。
- 临时文件加密存储。
- 临时文件自动清理。

### 9.2 相册

相册必须按 Telegram 的媒体分组标识聚合后处理：

- 等待同一媒体组的消息收齐或达到聚合超时。
- 按来源顺序生成目标媒体组。
- 目标端允许产生多条目标消息。
- 保存来源消息与目标消息的一对多映射。
- 不得把相册静默拆成互不相关的单条消息。
- 相册部分失败时展示明确状态和失败原因。

## 10. 权限和内容保护

### 10.1 权限检查

保存规则和启用规则时，需要分别检查：

来源 A：

- 执行身份可以解析并访问 A。
- 执行身份可以读取 A 的新消息。
- 来源对象未被删除或限制访问。

目标 B：

- 执行身份仍是 B 的成员或管理员。
- 群组允许发送消息。
- 频道具备发帖权限。
- 当前消息类型允许发送。
- 目标对象未被删除或限制发送。

权限检查只能作为预检查。实际发送每条消息前仍需要重新检查规则状态、执行身份和目标权限。

### 10.2 私有群和频道

允许私有群和私有频道作为来源或目标，但必须满足执行身份实际具备访问权限。

配置页面需要向用户说明：

> 消息可能会被重新发布到目标群或频道，请确认目标成员具有查看这些内容的权限。

### 10.3 受保护内容

来源启用内容保护时，两种同步模式都禁止处理：

- 禁止原生转发。
- 禁止复制内容。
- 禁止下载后重新上传绕过保护。
- 禁止转发失败后自动切换为复制。

受保护消息应标记为“已跳过”，并记录“来源内容受保护”的原因。

## 11. 服务端运行要求

### 11.1 常驻运行

同步 Worker 必须在服务端持续运行，浏览器关闭、页面切换或用户退出当前页面不影响已启用规则。

### 11.2 连接管理

- 同一执行身份使用共享 Telegram 连接管理器。
- 同一条规则同一时间只能有一个活跃 Worker。
- Worker 需要通过租约获取规则执行权。
- 租约续期失败后停止拉取和发送。
- 旧 Worker 不能在租约失效后继续写入状态或发送消息。
- Worker 异常退出后，租约过期后允许其他 Worker 接管。

### 11.3 服务端部署

部署到服务器时需要支持：

- 持久化规则配置。
- 持久化执行身份和安全凭证引用。
- 持久化同步任务和消息映射。
- 持久化同步游标。
- Worker 重启后恢复任务。
- 服务端监控和告警。

## 12. 状态模型

### 12.1 规则状态

| 状态 | 说明 |
| --- | --- |
| 草稿 | 配置已保存，但尚未开始同步 |
| 运行中 | 允许接收和发送新的同步任务 |
| 已暂停 | 不创建新的同步任务 |
| 异常 | 权限、账号、目标或持续运行出现问题 |
| 已删除 | 逻辑删除，不再接收新消息 |

### 12.2 消息任务状态

| 状态 | 说明 |
| --- | --- |
| 待处理 | 已接收来源消息，等待发送 |
| 发送中 | 正在调用 Telegram 发送接口 |
| 已发送 | 已确认得到目标消息 |
| 重试中 | 遇到可恢复错误，等待下一次尝试 |
| 已跳过 | 明确不支持或不允许同步 |
| 失败 | 达到重试条件或发生不可恢复错误 |
| 未知结果 | Telegram 可能已接受请求，但服务端无法确认结果 |

“未知结果”不能直接当作普通网络错误自动重试，否则可能造成重复消息。需要提供查询、标记已发送、跳过或带风险重试等人工处理选项。

## 13. 可靠性要求

- 同一来源消息不能因为重复更新而生成多个同步任务。
- 同一规则内按来源消息顺序发送。
- 网络错误使用有限次数的指数退避重试。
- Telegram 限流错误按照服务端返回的等待时间处理。
- 权限错误、会话失效和内容受保护不得无限重试。
- Worker 重启后不能丢失已持久化的待处理消息。
- 每条成功消息保存来源消息与目标消息映射。
- 相册支持一个来源消息对应多个目标消息。
- 规则暂停、删除或配置变更后，旧任务必须失效。
- 拒绝 A → A 配置，并为未来多规则预留环路检测能力。

投递语义定义为：

> 持久化至少一次投递；正常重试不重复；外部请求结果不明确时进入未知结果状态。

系统不承诺绝对的 exactly-once 投递。

## 14. 安全和隐私要求

- 用户账号 Session 使用专用安全凭证存储。
- Bot Token 使用专用安全凭证存储。
- 凭证不能进入前端、普通数据库字段、日志、队列和监控。
- 规则、任务和消息映射必须绑定用户和执行身份。
- 发送前重新校验规则归属、执行身份和目标会话。
- 日志不记录消息正文、媒体内容、手机号、完整链接或凭证。
- 媒体临时文件需要加密并设置自动清理时间。
- 支持按账号、Bot 和规则撤销执行权限。
- 用户可以查看当前已连接的执行身份。
- 权限失效、Session 失效或账号被撤销时，规则进入异常状态并停止发送。

## 15. 第一阶段不包含的内容

- 多条同步规则。
- 一个来源同步到多个目标。
- 历史消息补同步。
- 编辑和删除联动。
- 关键词过滤。
- 消息类型过滤配置。
- 回复、评论和 Topic 关系同步。
- 自动翻译、改写或内容审核。
- 转发和复制模式自动互相降级。

## 16. 验收标准

### 配置与权限

- 左上角可以进入“定制功能”。
- 可以进入“消息同步”功能。
- 来源 A、目标 B、执行身份和同步模式均可配置。
- A 和 B 相同时不能保存或启用。
- 无法读取 A 时不能启用。
- 无法向 B 发送消息时不能启用。
- 私有群和频道可以在有权限时被选择。
- 保存后默认进入草稿状态。

### 两种模式

- 保留来源转发模式能够保留来源信息。
- 隐藏来源复制模式不展示原始来源信息。
- 两种模式支持文本、常见媒体、普通文件和相册。
- 转发失败不会自动切换为复制。
- 受保护内容在两种模式下均不会被同步。
- 不支持的消息会显示跳过或失败原因。

### 服务端运行

- 规则启用后，关闭网页不影响同步任务运行。
- 服务端重启后能够恢复规则和待处理任务。
- 同一规则不会被多个 Worker 同时执行。
- Worker 失效后，其他 Worker 可以在租约过期后接管。

### 消息同步

- 只同步启用之后的新消息。
- 同一来源消息不会因重复更新而重复创建任务。
- 同一规则内消息按顺序发送。
- 文本、图片、视频、音频和文件可以按支持范围同步。
- 相册按媒体组处理，目标端映射完整。
- 临时错误可以重试。
- Telegram 限流按照等待时间处理。
- 权限错误不会无限重试。
- 外部发送结果不明确时进入未知结果状态。

### 暂停、恢复和删除

- 暂停后不创建新的同步任务。
- 暂停期间产生的消息不自动补发。
- 恢复后只处理恢复之后的新消息。
- 删除后不再同步新消息。
- 删除后旧 Worker 不能继续发送。
- 删除规则不会删除目标端已经发送的消息。

## 17. 后续扩展方向

1. 多规则和一对多同步。
2. 历史消息补同步。
3. 编辑和删除同步。
4. 回复关系和论坛 Topic 映射。
5. 关键词、时间和消息类型过滤。
6. 更完整的消息类型支持。
7. 复制模式的前缀、签名和格式化配置。
8. 更完善的未知结果查询和人工处理中心。
